# leads-niche-hub

חיבור בין שתי אפליקציות של SHAHAR AI PRODUCTIONS:

- `niche-hunter/`: צייד הנישות. עותק של `C:\Users\User\Downloads\niche-hunter.html`
- `leads-radar/`: Leads Radar. עותק של הריפו [shaharprod/leads-radar](https://github.com/shaharprod/leads-radar) (commit a63688f)
- `needs-map/`: מפת צרכים דו-צדדית (חדש, 28.9.2026)
- `index.html`: דף הבית שמחבר ביניהן

## מה נוסף בחיבור
- צייד הנישות → Leads Radar: לכל הזדמנות ה-AI מחזיר `lead_keywords` (סוגי עסקים מקומיים). לחיצה פותחת את Leads Radar עם `?kw=`.
- Leads Radar → צייד הנישות: הכפתור «💡 רעיון למוצר לנישה הזו» פותח את `niche-hunter/?seed=...&auto=1`.

## בידוד מהמקור
- המקורות לא שונו.
- האחסון בדפדפן בנפרד: `hub_lr_*` / `hub_nh_*` במקום `lr_*` / `nh_*`, כדי שהלידים של Leads Radar המקורי (אותו דומיין shaharprod.github.io) לא ייגעו.
- בפעם הראשונה ההגדרות (מפתחות API, מיתוג) מועתקות **לקריאה בלבד** מ-Leads Radar המקורי. אין כתיבה למפתחות המקוריים.
- שרת הביקורת (Cloud Function) משותף לשתי הגרסאות.

## מפת הצרכים (`needs-map/`)
- מה הלקוחות כותבים (ביקורות Google Places, עד 5 לעסק; בסריקה עמוקה דרך Apify עד 200 לעסק כולל תשובות הבעלים) ומחפשים (השלמות חיפוש של גוגל + שם העיר).
- כל ביקורת מסווגת ל-8 צרכים (AI: Gemini/Claude מההגדרות הקיימות, או מילות מפתח כגיבוי). כל עסק משויך לשכונה הקרובה מ-OpenStreetMap.
- כאבים ושאיפות של בעלי העסקים: אין אתר, אין הזמנה, סוגר לפני 19:00, דירוג נמוך, אחוז מענה לביקורות, תשובות מתגוננות, סימני צמיחה.
- הזדמנויות חיבור: לקוחות ← עסק שפותר, תובנה ← עסק שסובל (הודעת וואטסאפ מוכנה), כאב העסק ← הפתרון.
- ייבוא מהסריקה האחרונה ב-Leads Radar (בלי עלות Google נוספת), ייצוא CSV ו-JSON, מצב הדגמה (`?demo=1`).
- אחסון: `hub_nm_*`. טוקן Apify נשמר רק בדפדפן. שמות כותבי הביקורות לא נשמרים.
- כפתורי כניסה: «🧭 מפת צרכים לאזור הזה» ב-Leads Radar, ו«🧭 מה אנשים כותבים ומחפשים כאן?» במפת הכאבים של צייד הנישות.
